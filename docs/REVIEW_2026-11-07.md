## What the app is

Think of Vesta as a personal shopper at a department store who has a lookbook under the counter. You describe what you want (or show a photo), the shopper talks it through, flips to matching pages in the lookbook, and hands you tags for items you can buy at the partner shops next door. Vesta never sells anything itself.

In code terms: one Node/Express process serves the React UI and the `/api` routes. Chat goes to Claude (`server/services/fashionAi.ts`); before Claude answers, a rule-based planner (`fashionIntent.ts`) decides the shopper's job (browse, similar, combine, color, style) and who it is for, and retrieval pulls cards from the affiliate catalog in Postgres or the local DeepFashion image set. If Claude is unreachable, a rule-based fallback answers instead. Cart, click-out links (`/api/go/:id`) and chat history live in Postgres; virtual try-on is a demo that needs a separate Python service.

## How to run and test (from a fresh clone)

```bash
npm ci
cp .env.example .env            # set ANTHROPIC_API_KEY for real Claude answers
npm run docker:db               # or any Postgres 16 matching DATABASE_URL
npm run db:push                 # applies the schema, including the new chat_histories.session_id
npm run catalog:ingest          # 12 demo products
npm run check                   # typecheck, now clean
npm test                        # 30 tests: unit + the real API against Postgres
npm run eval:chat               # 55 scripted chat checks, no tokens
npm run dev                     # http://localhost:3000
```

`npm run eval:retrieval` needs the DeepFashion dataset in `server/data/DeepFashion-MultiModal/` (gitignored). Without it, 5 of 26 checks fail and the script now says so up front.

CI (`.github/workflows/ci.yml`) runs typecheck, schema, tests against a Postgres service and the chat eval on every push and pull request. It needs no secrets.

## What was wrong and what changed

Each fix was test-first: the test was run against the old code and failed for the reason shown, then passed after the change.

| # | Finding | Evidence before | After |
|---|---|---|---|
| 1 | Chat never reached Claude. All three model IDs (`claude-3-5-sonnet-20241022`, `claude-3-sonnet-20240229`, `claude-3-haiku-20240307`) are retired per Anthropic's deprecation page (retired 2025-10-28, 2025-07-21, 2026-04-20). Every call failed and users got the rule-based fallback, silently. | Model list in `fashionAi.ts` | `server/services/claudeModels.ts`: `claude-sonnet-5-5`, then `claude-haiku-5-5`; `ANTHROPIC_MODEL` puts another first. A test fails if a model ID is hard-coded in the chat service again. |
| 2 | Anyone could read and overwrite anyone's chats. History was one shared "local user"; `/api/chat/histories/1` returned every chat to every visitor, and any chat could be read or replaced by its number. | Integration test: a second browser saw the first browser's chat (`expected [1, 2] to not include 2`) | Chats belong to the browser cookie (`vesta_sid`), same as the cart. New column `chat_histories.session_id`. Other browsers get 404. The client needed no change. |
| 3 | The buy link redirect would follow any stored value, including `javascript:` links. | Test: `GET /api/go/:id` returned 302 to `javascript:alert(1)` | Checked twice: feed ingest skips rows whose buy or image link is not http(s), and the redirect refuses with 422. |
| 4 | No limits on uploads. Bodies up to 50 MB and any image type were passed to Claude, which accepts at most 10 MB per base64 image, JPEG/PNG/GIF/WebP only. | Tests: a BMP and a 26 MB body both returned 200 | Body cap 25 MB (two images for try-on); per-field rules in `server/validation.ts` with a plain error message. |
| 5 | No throttle on the paid AI route. One script could run up the Anthropic bill. | Test: 4 rapid chats all 200 | 20 per minute per client IP by default (`CHAT_RATE_LIMIT_PER_MIN`), `429` with `Retry-After`. Invalid requests are rejected before they count. |
| 6 | Typecheck failed (`server/vite.ts`, `allowedHosts`). | `tsc` error TS2322 | `npm run check` exits 0. |
| 7 | Known vulnerable packages: 21 in production dependencies, 1 critical (`proxy-addr`). | `npm audit --omit=dev` | Non-breaking fixes applied: 6 left (0 critical, 3 high). Those need major upgrades, see below. |
| 8 | Retrieval eval reported 5 failures on any fresh clone because the dataset is gitignored. | `21/26 passed`, all failures `n=0` | Warns up front and labels the failures as expected without the corpus. |

Also: app setup moved into `server/app.ts` (`createApp()`), used by `server/index.ts` and by the tests, so the tests run the same server production runs. Added Vitest, `npm test`, and the CI workflow.

Old chat rows from before this change have no `session_id`, so nobody sees them. On a local machine that only hides test chats; nothing is deleted.
